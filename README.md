# RunQの森

重要なRailsコードを「打って覚える」タイピング練習アプリです。
MVCの基本構文・ActiveRecordクエリ・Gemfile/設定コマンドなど、実務でよく使うコードを
優しい(なぞる)・普通(ヒントあり)・難しい(ノーヒント)の3段階で練習できます。
ログインすれば自分の好きなコードを追加して練習することも可能です。

**公開URL: https://runqapp.onrender.com**

トップページの「ゲストログイン」から、登録なしでそのまま試せます。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 3段階の練習 | 同じコードを、手がかりを減らしながら繰り返す |
| 採点と解説 | 正答率・ミス数・タイムを記録し、終了後に解説を表示 |
| 今日の練習 | 忘れかけた頃のコードを自動で選んで出題する |
| 写経モード | 貼り付けた自分のコードを、3段階の難易度で写せる |
| 和訳モード | 貼り付けたコードを、全体の役割・1行ごと・単語の3段階で日本語にする |
| メモ | 気づいた点を練習しながら書き留める |
| 続けた記録 | 連続日数と今週の練習日を表示する |
| 効果音とBGM | 音声ファイルを持たず、波形から合成する |
| 利用状況 | 登録者数・練習回数・つまずかれやすいコードを集計(管理者のみ) |

## セットアップ

開発環境は Docker Compose で立ち上げます。Docker Desktop が動いていれば、
Ruby や PostgreSQL を個別に入れる必要はありません。

```bash
git clone https://github.com/stephano222/RunQapp.git
cd RunQapp
docker compose up -d
```

初回はイメージの構築と gem の導入で数分かかります。
起動したら、データベースを用意して初期データを入れます。

```bash
docker compose exec web bundle exec rails db:prepare
docker compose exec web bundle exec rails db:seed
```

http://localhost:3001 で開きます。ログイン画面の「ゲストログイン」からすぐ試せます。

### テストの実行

```bash
docker compose exec web bundle exec rspec
```

243本あり、手元では2秒ほどで終わります。

### 管理者にする

利用状況の画面は管理者だけが開けます。先に新規登録したうえで、
そのアドレスを環境変数 `ADMIN_EMAIL` に渡してシードを流すと権限が付きます。
ログインするたびにも確認するので、後から登録した場合も次のログインで反映されます。

### 停止と後片付け

```bash
docker compose down          # 止める(データは残る)
docker compose down -v       # データベースの中身ごと消す
```

## 1. サービス概要

- Runteqに貢献できるアプリを作りたい。最速MVP（エッセンシャル思考）で、「Runteqのカリキュラムを最も効率よく学べる」アプリ、「Web界隈の人材を最速で作りたい」という想いから生まれたのがこのアプリです。　写経や和訳もできます。

- webエンジニアになるために、学び始めた人たちにを最速でMVPで（エッセンシャル思考で）技術を身につけさせることが可能なアプリ

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情


仕事中の休憩中に、何のアプリを出そうかなと考えていた時に思いつきました。自分の作りたいアプリではなく、RUNTEQに貢献できるアプリならもっと皆の需要があるのではないか、最低限の使用と時間で高速化できる哲学を詰め込んだアプリを実装すれば、長く使ってみんなが幸せになれるのではないかと思いました。

### 2-2. なぜそれが「気になった」のか

画家のフェルメールやベラスケスが書いた有名なマルタとマリアの場面の絵「マルタ、マルタ、あなたは多くのことに思い悩み、心を乱している。 しかし、必要なことはただ一つだけである。 マリアは良い方を選んだ。」（ルカ10,41-42）この哲学の部分をRUNTEQで学んだMVPという考えと合致させ、十分なものにとらわれるのではなく、必要なもの（エッセンシャル思考）に目の付け所と集中と労力を注ぐことで、エッセンシャル思考をアプリの根本の中に哲学として組み込んで実現しました。
とにかく最速、必要なものに集中することで多くの人に役に立てると思ったからです。

---

## 3. 課題の整理

### 3-1. 表に見えている困りごと

その体験の中で、最初に感じた「困りごと」は何ですか？

宗教性があまり人に受け入れられないかもしれない。自分が毎日使用したいアプリであるために、自分が毎日見たい言葉も、一般的ではないかもしれない。

---

### 3-2. 本当に解決したい課題は何か
→ 本当に解決したい課題：エッセンシャル思考（MVP）がいかに人生にとって重要な思想か。

- なぜ？　人は必要不可欠なことに集中するから、十分余計なものが後からやってくる
- なぜ？　人は欲望に塗れているから、本質を見失う
- なぜ？　毎日心がけなくてはいけないのは、人より多く得ることでもなく、人に勝つことでもなく、自分が神様から与えられた人生を生きて、個性を発揮して、一人の役割として自分に与えられた才能を発揮すること。


→ この考え方は株式市場にも応用できる。利益を得ようとすると、逆に本当に必要なもの、生き残るために必要なものを失う。
神話上での災害もそういう教訓がずっとある。自分の命（必要不可欠）が大事なのに、十分余計なもの（お金、利益）に固執して、必要不可欠なものを失う。株式市場では、利益を第一にすると、資金を奪われる。重要なのは１、生き残ること　２、１を忘れないこと

  - 理由：その環境特有のハードルを、アプリの仕組みでどう解消しますか？　解説や写経や和訳のサービスでMVP思考を身につけつつ、エンジニアとしての技術も身につける。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

このサービスは、ユーザーがどのような状況・きっかけで
「使ってみよう」と思い、利用を始めるサービスでしょうか？


- 学び初めの段階で、英語の意味や、コードの意味やコードリーディングがまだうまくできない方々
- テストユーザーで試してみる。
- 楽しく続けられる点
- 企業や組織が、このサービスを導入する判断をする理由は何か　　初学のエンジニアが研修として利用できる
- どうしたら機密情報や業務データを、個人開発のサービスに登録したいと思ってもらえるか　デプロイの機能や環境構築、セキュリティをもっとしっかりして、脆弱性をなくす。
- 既存の運用やツールから、乗り換えるハードルはどこにあるか　　特にないが、長年使っていて余程の差別化がない限り、乗り越えは難しいと感じる。

### 5-2. それでも自分が作りたい理由

- 音もでなければ、その場で和訳や長いコードを写経できる場が提供されていないので、直感的に楽しく写経ができない。

### 5-3. 差別化を「体験価値」で表現する

- 私のアプリの差別化ポイント：　直感的に気軽に楽しく、気分的に障害が生じるポイントをすべて解消し、一元化して一つのアプリですべての障害を突破できることで、初心者でも毎日楽しく挫折なく写経ができる。

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- 行動の変化：　毎日直感的に写経できる環境にあるので、ただ頭に入れるだけになりがちで、AIに頼り理解が不足してしまう部分に、コードを書くという経験を無意識に身につけさせることができる。
- 気持ちの変化：　毎日、技術の向上が見込めるため、日々成長を感じることができる。
- 考え方の変化：　人生にとって一番重要なエッセンシャル思考が無意識に身についていく。

### 6-2. 価値を一文で表す

「このサービスはまだコードも読めない人が、気軽に写経や英語の意味を理解しながらコードを学ぶことができるようになるサービス」
